Ginko Docs arbeitet zuerst statisch und unterstützt Nitro weiterhin vollständig. Wähle das kleinste Profil, das deine benötigten Laufzeitfunktionen liefert.

## Deployment-Ziel wählen

| Profil | Seitenauslieferung | Markdown auf derselben URL | MCP |
| --- | --- | --- | --- |
| Rein statisch | Nur generierte Dateien | Nein; verwende `/raw/**.md` | Nein |
| Statisch + Provider-Routing | Generierte Dateien mit einer kleinen Host-Routing-Funktion | Ja | Nur wenn zusätzlich eine Nitro-Funktion läuft |
| Nitro-Laufzeit | Nitro-Server, Serverless-Funktion oder Container | Ja | Ja |

Nutze **Statisch + Provider-Routing** als normales Dokumentationsprofil. Menschliche Seiten, Raw-Markdown, LLM-Indizes, Sitemaps und Social Images bleiben generierte Dateien. Die Provider-Funktion wählt nur anhand des eingehenden `Accept`-Headers die richtige Darstellung. Nutze **Rein statisch**, wenn null Laufzeit-Ausführung wichtiger ist als Aushandlung auf derselben URL. Nutze **Nitro-Laufzeit**, wenn ein portabler Serverpfad wichtiger ist als statische Auslieferung.

Das Menü zum Kopieren von Markdown verwendet die explizite Raw-Route. Es funktioniert auf statischem Hosting, wenn die generierten `/raw/**.md`-Dateien ausgeliefert werden. Die Einträge für ChatGPT, Claude und MCP sind Darstellungsoptionen; Änderungen an `markdownActions` aktivieren oder deaktivieren keine Server-Routen.

## Statische Website generieren

Statische Auslieferung ist der Standard:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    agent: { delivery: "static" },
  },
});
```

Starte die Nuxt-Generierung in der konsumierenden Anwendung:

```bash [Terminal]
pnpm generate
```

Deploye das vollständige Verzeichnis `.output/public`. Ginko Content liefert öffentliche Seitenrouten, Raw-Markdown und LLM-Kataloge an den Prerender-Prozess. Der Layer fordert außerdem `/sitemap.xml`, `/robots.txt`, `/llms.txt` und `/llms-full.txt` explizit an.

Stelle das generierte Verzeichnis vor dem Release über HTTP bereit:

```bash [Terminal]
pnpm dlx serve .output/public
```

Das Öffnen einer HTML-Datei über `file://` testet weder Host-Routing noch Asset-Pfade, Weiterleitungen oder Fallbacks.

## Provider-Routing ergänzen

Die Routing-Schicht muss einen expliziten `text/markdown`-Bereich verlangen, gewichtete `q`-Werte vergleichen, Assets und Maschinen-Endpunkte ausschließen, die öffentliche URL erhalten und `Vary: Accept` setzen. Eine fehlende Raw-Datei muss eine echte `404` mit einem kurzen Markdown-Hinweis bleiben.

Das Repository enthält ausführbare Rezepte mit gemeinsamen Vertragstests:

- [Vercel Routing Middleware](https://github.com/lupinum-dev/ginko-docs/blob/main/docs/middleware.ts)
- [Cloudflare Worker](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/cloudflare-worker.ts)
- [Netlify Edge Function](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/netlify-edge.ts)
- [Nginx](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/nginx.conf) und [Caddy](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/Caddyfile) als Nitro-Reverse-Proxys

Lege bei Vercel `middleware.ts` neben die `package.json` der deployten App und installiere `@vercel/functions`. Die Ginko-Docs-Website nutzt dieses Profil in Produktion. Cloudflare Workers müssen das statische Verzeichnis als `ASSETS` binden und den Worker vor den Assets ausführen. Netlify muss die Edge Function für Seitenpfade deklarieren.

## Nitro-Deployment bauen

Wähle die Laufzeit-Auslieferung explizit:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    agent: { delivery: "runtime" },
  },
});
```

Baue den Produktionsserver und prüfe ihn lokal:

```bash [Terminal]
pnpm build
pnpm preview
```

Deploye `.output` mit dem vom Host benötigten Nitro-Preset. Provider-Clients und Zugangsdaten gehören ausschließlich in Server-Dateien. Der Dateisystem-Provider verwendet den beim Build erzeugten Content-Snapshot; ein externer Provider kann zur Request-Zeit lesen, wenn Laufzeit und Zugangsdaten am Ziel verfügbar sind.

Nitro verarbeitet gewichtete Markdown-Aushandlung, Response-Link-Header, Markdown-Fehlerantworten und `/mcp`. Ein CDN darf diese Antworten cachen, muss aber `Accept` weiterleiten und den Cache nach `Accept` trennen.

## Öffentliche URLs konsistent halten

Verwende überall dieselbe Produktions-Origin:

```json [site.json]
{
  "name": "Example Docs",
  "description": "Dokumentation für Example.",
  "whenToUse": "Nutze diese Website, um Example kennenzulernen und zu betreiben.",
  "url": "https://docs.example.com"
}
```

```ts [content.config.ts]
import { defineGinkoDocsConfig } from "@lupinum/ginko-docs/content";
import site from "./site.json" with { type: "json" };

export default defineGinkoDocsConfig({
  site,
});
```

```ts [app/app.config.ts]
import site from "../site.json";

export default defineAppConfig({
  ginkoDocs: {
    site: {
      url: site.url,
    },
  },
});
```

```ts [nuxt.config.ts]
import site from "./site.json" with { type: "json" };

export default defineNuxtConfig({
  extends: ["@lupinum/ginko-docs"],
  site: { url: site.url },
  i18n: { baseUrl: site.url },
});
```

Ginko Docs verwendet die URL aus App Config für Canonical-, Alternate-, Raw- und MCP-Links. Ginko Content liest die kanonische Origin aus Nuxt Site.

## Ausgelieferte Ausgabe prüfen

Prüfe das Deployment selbst, nicht nur das lokale Build-Log:

- Lade Startseite, erste Dokumentationsseite, eine verschachtelte Seite und eine fehlende URL direkt.
- Öffne repräsentative Seiten in jeder konfigurierten Sprache und kontrolliere Canonical- und Alternate-Links.
- Folge Bereichsumschalter, Sidebar-Links, Vor-/Zurück-Links und Suchergebnissen.
- Prüfe, ob `/sitemap.xml`, `/robots.txt`, `/llms.txt` und `/llms-full.txt` mit dem erwarteten Content-Type antworten.
- Rufe eine generierte `/raw/**.md`-URL ab und prüfe, dass Entwürfe und private Daten fehlen.
- Fordere eine Seite mit bevorzugtem HTML und eine mit bevorzugtem Markdown an. Prüfe Content-Type und `Vary: Accept`.
- Fordere eine fehlende Seite mit bevorzugtem Markdown an. Prüfe eine echte `404` und hilfreiche Links.
- Rufe `/.well-known/ai-catalog.json`, `/mcp/server-card` und `/mcp` nur auf, wenn das Laufzeitprofil MCP bewirbt.
- Prüfe Browser- und Server-Logs auf Hydration-Fehler, fehlende Assets und fehlgeschlagene Social-Image-Routen.
