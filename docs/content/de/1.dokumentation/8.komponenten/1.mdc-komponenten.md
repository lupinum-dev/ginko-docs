Wähle eine Komponente, probiere das Beispiel aus und kopiere das Markdown in deine Seite. Diese Referenz enthält alle 33 eingebauten Tags, einschließlich normaler Bilder. Ersetze die Beispieltexte, Links und Bildpfade durch deine eigenen Inhalte.

MDC bedeutet Markdown Components. Damit ergänzt du Markdown um strukturierte Blöcke. Eine **Eigenschaft** (auch **Prop**) verändert eine Komponente, etwa ihren Titel. Ein **Slot** ist der Inhalt zwischen der öffnenden und der schließenden Zeile.

## Hier beginnen

- Schreibe Texteigenschaften in geschweifte Klammern: `::note{title="Bevor du beginnst"}`.
- Schreibe Wahrheitswerte (`true` oder `false`), Listen und Objekte in einen YAML-Block zwischen `---`-Zeilen, direkt unter dem öffnenden Tag.
- Schließe einen Block mit zwei Doppelpunkten. Verschachtelte Kinder beginnen und enden mit drei Doppelpunkten. Ergänze pro weiterer Ebene einen Doppelpunkt; die Beispiele unten zeigen vollständige Paare.
- Verwende `:kbd[Enter]` für eine Komponente innerhalb eines Satzes.
- Eigenschaften sind optional, sofern sie nicht als **erforderlich** markiert sind. Ohne optionale Texteigenschaft entfällt dieser Text. Namen und Werte der Eigenschaften bleiben auch auf deutschen Seiten Englisch.
- Verwende statische Werte. Vue-Bindings, Events, Direktiven, beliebige Styles und boolesche Attribute ohne Wert sind nicht erlaubt.

Links mit `$docs/` verweisen auf Seiten der Docs-Sammlung. Ersetze sie durch eine passende Seite deiner Website; siehe [Inhaltslinks]($docs/authoring/links). Die Bildbeispiele verwenden eine Datei aus dem Ordner `public/images/` dieser Website. Lege dort dein eigenes Bild ab, bevor du ein Bildbeispiel übernimmst.

Springe über das Inhaltsverzeichnis zur gewünschten Komponente. Zusammengehörige Tags wie `tabs` und `tab` stehen im selben Abschnitt.

## Darstellung

`appearance="quiet"` verwendet eine zurückhaltende Fläche. `appearance="tint"` ergänzt eine farbige Fläche. Die Eigenschaftstabellen zeigen, welche Komponenten diese Einstellung unterstützen. Ohne Angabe gilt zuerst die Website-Einstellung der Komponentenfamilie, dann die globale Einstellung. Der eingebaute Rückfallwert ist `quiet`. Eine Karte übernimmt zusätzlich die Darstellung ihres umgebenden `cards`-Blocks, sofern sie keine eigene Angabe hat.

Vergleiche beide Varianten in der [Komponentenübersicht]($docs/components/component-showcase).

## note

Ergänze einen hilfreichen Hinweis.

::note{title="Merken" appearance="tint"}
Speichere deinen Entwurf, bevor du den Editor schließt.
::

**In deine Markdown-Datei kopieren:**

````mdc [content/docs/component-example.md]
::note{title="Merken" appearance="tint"}
Speichere deinen Entwurf, bevor du den Editor schließt.
::
````

| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `title` | Text. Standardmäßig kein Titel. |
| `icon` | Icon-Name wie `lucide:info`. Ohne Angabe erscheint das Icon für note. |
| `appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |

Inhalt: Markdown im Standard-Slot.

## accordion und accordion-item

Verberge optionale Details hinter einer Frage. Wähle die Frage, um sie zu öffnen oder zu schließen.

::accordion
---
type: single
collapsible: true
defaultValue: preparation
---
:::accordion-item{value="preparation" title="Was soll ich vorbereiten?"}
Bereite den Text und ein Bild mit Alternativtext vor.
:::
:::accordion-item{value="review" title="Wer prüft die Seite?"}
Bitte eine weitere Person aus dem Redaktionsteam darum.
:::
::

**In deine Markdown-Datei kopieren:**

````mdc [content/docs/component-example.md]
::accordion
---
type: single
collapsible: true
defaultValue: preparation
---
:::accordion-item{value="preparation" title="Was soll ich vorbereiten?"}
Bereite den Text und ein Bild mit Alternativtext vor.
:::
:::accordion-item{value="review" title="Wer prüft die Seite?"}
Bitte eine weitere Person aus dem Redaktionsteam darum.
:::
::
````

| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `accordion.type` | `single` (Standard) öffnet einen Eintrag; `multiple` erlaubt mehrere. |
| `accordion.collapsible` | Wahrheitswert. Standard: `true`. Erlaubt im Modus single, den offenen Eintrag zu schließen. |
| `accordion.defaultValue` | Anfangs offener Eintrag; standardmäßig keiner. Bei `single` ein Textwert, bei `multiple` eine YAML-Liste von Textwerten. |
| `accordion.appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |
| `accordion-item.value` | Eindeutige Textkennung. Wird ohne Angabe erzeugt. Für `defaultValue` selbst festlegen. |
| `accordion-item.title` | Frage oder Überschrift. Standardmäßig kein Titel. |
| `accordion-item.content` | Einfacher Inhaltstext. Standardmäßig leer; der Standard-Slot mit Markdown folgt danach. |

Setze nur `accordion-item`-Kinder in `accordion`. Jeder Eintrag erlaubt Markdown im Standard-Slot, einen `#title`-Slot statt der title-Eigenschaft und einen `#content`-Slot statt der content-Eigenschaft.

:::
:::tab{label="Prüfen" icon="lucide:check"}

:::


| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `tabs.layout` | `separate` (Standard) oder `line`. Verändert die Darstellung der Tab-Leiste. |
| `tabs.padded` | Wahrheitswert. Standard: `true`. Ergänzt Abstand um den Inhalt. |
| `tabs.appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |

## cards und card

Biete eine kleine Auswahl an Möglichkeiten. Eine Karte mit `to` wird zum Link.

::cards{cols="2"}
:::card{title="Seite schreiben" description="Beginne mit deinem Text." icon="lucide:file-pen-line" to="$docs/authoring/write-content" footer="Anleitung öffnen"}
Gliedere das Thema mit Überschriften.
:::
:::card{title="Links ergänzen" description="Verbinde hilfreiche Seiten." icon="lucide:link" to="$docs/authoring/links"}
Beschrifte jeden Link eindeutig.
:::
::

**In deine Markdown-Datei kopieren:**

````mdc [content/docs/component-example.md]
::cards{cols="2"}
:::card{title="Seite schreiben" description="Beginne mit deinem Text." icon="lucide:file-pen-line" to="$docs/authoring/write-content" footer="Anleitung öffnen"}
Gliedere das Thema mit Überschriften.
:::
:::card{title="Links ergänzen" description="Verbinde hilfreiche Seiten." icon="lucide:link" to="$docs/authoring/links"}
Beschrifte jeden Link eindeutig.
:::
::
````

| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `cards.cols` | `1`, `2` (Standard) oder `3`. Maximale Spaltenzahl; auf schmalen Bildschirmen stehen Karten untereinander. |
| `cards.appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |
| `card.title` | Überschrift. Standardmäßig kein Titel. |
| `card.description` | Kurzer Text unter dem Titel. Standardmäßig keine Beschreibung. |
| `card.footer` | Text im Fußbereich. Standardmäßig kein Fußbereich. |
| `card.to` | Seitenreferenz, Website-Pfad oder externe URL. Standardmäßig kein Link. |
| `card.target` | Linkziel, etwa `_blank` für einen neuen Tab. Standard: aktueller Tab. |
| `card.icon` | Icon-Name. Standardmäßig kein Icon. |
| `card.iconColor` | `muted` (Rückfallwert), `foreground`, `primary`, `info`, `success`, `warning` oder `destructive`. |
| `card.img` | Bildreferenz. Standardmäßig kein Bild. Dekorativ: Karten haben keine Eigenschaft für Bild-Alternativtext. |
| `card.showLinkIcon` | Wahrheitswert. Standard: `true`. Zeigt den ausgehenden Pfeil bei externen Links. |
| `card.horizontal` | Wahrheitswert. Standard: `false`. Platziert das Icon der Kopfzeile neben Titel und Beschreibung. |
| `card.appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |

Verwende `card` einzeln oder innerhalb von `cards`. Der Standard-Slot enthält Markdown. Die benannten Slots `#title`, `#description` und `#footer` ersetzen die jeweiligen Texteigenschaften. Setze keinen weiteren Link oder interaktiven Schalter in eine verlinkte Karte.

Für einen formatierten Fußbereich schreibst du die Slot-Markierung auf eine eigene Zeile:

```mdc [content/docs/component-example.md]
::card{title="Checkliste der Redaktion"}
Lies den Entwurf laut vor.

#footer
**Bereit zur Durchsicht**
::
```

  - title: Inhalte schreiben
    to: $docs/authoring/write-content
    description: Gliedere deine Seite.
    icon: lucide:file-pen-line
  - title: Links ergänzen
    to: $docs/authoring/links
---
::

**In deine Markdown-Datei kopieren:**

````mdc [content/docs/component-example.md]
::read-more{title="Anleitungen zum Schreiben"}
---
links:
  - title: Inhalte schreiben
    to: $docs/authoring/write-content
    description: Gliedere deine Seite.
    icon: lucide:file-pen-line
  - title: Links ergänzen
    to: $docs/authoring/links
---
::
````

| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `title` | Überschrift. Standardmäßig kein Titel. |
| `links` | **Erforderlich.** YAML-Liste. Jeder Eintrag benötigt die Textfelder `title` und `to`. |
| `appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |

Jeder Link erlaubt zusätzlich `description`, `icon` und `target` (Text). Diese Angaben fehlen standardmäßig; Links öffnen im aktuellen Tab, sofern `target` das nicht ändert. Keine Slots. Eine leere Liste zeigt nichts an.

## api

Beschreibe strukturierte Felder in einem Referenzbereich. Verwende für einen kurzen, einfachen Vergleich eine Tabelle.

      - name: summary
        annotation: string

**In deine Markdown-Datei kopieren:**

````mdc [content/docs/component-example.md]
::api{title="Artikelfelder" icon="lucide:file-text"}

  - label: Felder
    entries:
      - name: title
        annotation: string
        required: true
        description: Die Überschrift des Artikels.
      - name: summary
        annotation: string
        optional: true
        description: Eine kurze Einleitung.
---
::
````

| Eigenschaft | Werte, Standard und Wirkung |
| --- | --- |
| `title` | Kopfzeilentext. Standardmäßig kein Titel. |
| `icon` | Icon-Name für die Kopfzeile. Standardmäßig kein Icon. |
| `method` | HTTP-Methode als Text, etwa `post`. Standardmäßig keine Methode. |
| `path` | Endpunktpfad, etwa `/api/articles`. Standardmäßig kein Pfad. |
| `groups` | **Für die Darstellung erforderlich.** Nicht leere YAML-Liste von Gruppen mit jeweils eindeutiger, nicht leerer `label`-Beschriftung und nicht leerer `entries`-Liste. Kein Standardwert. |
| `appearance` | `quiet` oder `tint`. Ohne Angabe gilt die Website-Einstellung. |

Der Inhalt gehört in `groups`. Der Standard-Slot ist laut Markdown-Policy erlaubt, wird aber nicht angezeigt. Verwende `title` für eine allgemeine Kopfzeile oder `method` mit `path` für einen Endpunkt.

Jedes Objekt in `entries` erlaubt diese Felder:

| Feld | Werte, Standard und Wirkung |
| --- | --- |
| `name` | **Erforderlich.** Nicht leerer Text, innerhalb der Gruppe eindeutig. |
| `annotation` | Typ als Text, etwa `string`. Standardmäßig nicht gesetzt. |
| `required` | Wahrheitswert. Standard: `false`. Ergänzt eine Markierung für erforderliche Felder. |
| `optional` | Wahrheitswert. Standard: `false`. Ergänzt `?` am Namen. Nicht mit `required: true` kombinieren. |
| `deprecated` | Wahrheitswert. Standard: `false`. Markiert ein veraltetes Feld. |
| `since` | Versionsangabe als Text. Standardmäßig nicht gesetzt. |
| `default` | Text, der den Standardwert des Feldes beschreibt. Zahlen und Wahrheitswerte in Anführungszeichen setzen, etwa `default: "false"`. Standardmäßig nicht gesetzt. |
| `description` | Text unter der Signatur. Backticks formatieren Inline-Code. Standardmäßig nicht gesetzt. |

Optionale Textfelder dürfen nicht leer sein, wenn du sie angibst. Ungültige Gruppen oder Einträge stoppen die Darstellung mit einer Fehlermeldung; sie werden nicht stillschweigend entfernt. Erzeugte Eintrags-IDs müssen eindeutig sein. Verwende über mehrere Bereiche hinweg unterschiedliche Kombinationen aus Gruppe und Name, damit keine doppelten Sprungmarken entstehen. Die [Anleitung zu API-Bereichen]($docs/components/api-reference) erklärt Kopfzeilenvarianten und Direktlinks zu Einträgen.

## Normales Markdown und eigene Komponenten

Absätze, Überschriften, **fetter Text**, *Hervorhebungen*, Listen, Links, Tabellen, Zitate, Trennlinien und Codeblöcke benötigen keinen MDC-Tag. Ginko Docs gestaltet sie automatisch. Zum Beispiel:

```md [content/docs/article.md]
## Vor dem Veröffentlichen

Prüfe **Namen** und *Termine*.

- Lies den Text.
- Öffne jeden Link.

> Mache die nächste Handlung deutlich.

| Aufgabe | Zuständig |
| --- | --- |
| Durchsicht | Redaktionsteam |

> [!NOTE]
> Speichere deinen Entwurf, bevor du den Editor schließt.
```

Hinweise im GitHub-Stil unterstützen `NOTE`, `TIP`, `IMPORTANT`, `WARNING` und `CAUTION`. Verwende eine der oben gezeigten Hinweiskomponenten, wenn du Titel, Icon oder Darstellung selbst festlegen möchtest.

Diese Seite beschreibt die eingebauten Komponenten für die Inhaltserstellung. Website-spezifische Tags benötigen eine eigene Registrierung; sie sind nicht auf jeder Ginko-Docs-Website verfügbar. Beispielsweise gehört `release-status` zum [Beispiel für eigene Komponenten]($docs/customization/custom-components) dieser Dokumentations-App. Bitte die Website-Entwicklung, eine neue Komponente zu registrieren, bevor du einen eigenen Tag verwendest.
