Choose a component, try the example, and copy its Markdown into your page. This reference covers all 33 built-in tags, including ordinary images. Replace the sample text, links, and image paths with your own content.

MDC means Markdown Components. It adds structured blocks to Markdown. A **property** (also called a **prop**) changes a component, such as its title. A **slot** is the content between its opening and closing lines.

## Start here

- Put text properties in braces: `::note{title="Before you start"}`.
- Put booleans (`true` or `false`), lists, and objects in a YAML block between `---` lines, directly below the opening tag.
- Close a block with two colons. Nested children open and close with three colons. Add one colon for each further level; the examples below show complete pairs.
- Use `:kbd[Enter]` for an inline component inside a sentence.
- Properties are optional unless marked **required**. Omit optional text to hide that text. Property names and values stay in English in translated pages.
- Use static values. Vue bindings, events, directives, arbitrary styles, and bare boolean attributes are not accepted.

Links beginning with `$docs/` refer to pages in the docs collection. Replace them with a matching page in your site; see [content links]($docs/authoring/links). Image examples use a file from this site's `public/images/` folder. Add your own image there before copying an image example.

Use the page contents to jump to a component. Paired tags, such as `tabs` and `tab`, share one section.

## Appearance

`appearance="quiet"` uses a restrained surface. `appearance="tint"` adds a colored surface. Each property table lists whether a component supports this setting. The default comes from the site's component-family setting, then its global setting; the built-in fallback is `quiet`. A card also inherits its surrounding `cards` appearance unless it has its own override.

Compare both styles in the [component showcase]($docs/components/component-showcase).


---

collapsible: true

---

:::
:::accordion-item{value="review" title="Who reviews the page?"}

````mdc [content/docs/component-example.md]
:::
::
````

| Property | Values, default, and effect |
| --- | --- |
| `accordion.type` | `single` (default) opens one item; `multiple` allows several. |
| `accordion.collapsible` | Boolean. Default: `true`. In single mode, allows closing the open item. |
| `accordion.defaultValue` | Initially open item value; none by default. Use a string for `single`, a YAML list of strings for `multiple`. |
| `accordion.appearance` | `quiet` or `tint`. Uses the site setting when omitted. |
| `accordion-item.value` | Unique text identifier. Generated when omitted. Set it when using `defaultValue`. |
| `accordion-item.title` | Question or heading text. No title by default. |
| `accordion-item.content` | Plain body text. No text by default; the default Markdown slot is rendered after it. |

Put only `accordion-item` children in `accordion`. Each item accepts default Markdown, a `#title` slot instead of the title property, and a `#content` slot instead of the content property.

  - label: Fields
    entries:
      - name: title
        annotation: string
        required: true
        description: The article heading.
      - name: summary

        optional: true

````mdc [content/docs/component-example.md]
---
::
````

| Property | Values, default, and effect |
| --- | --- |
| `title` | Header text. No title by default. |
| `icon` | Header icon name. No icon by default. |
| `method` | HTTP method text, such as `post`. No method by default. |
| `path` | Endpoint path, such as `/api/articles`. No path by default. |
| `groups` | **Required for rendering.** Non-empty YAML list of groups, each with a unique non-empty `label` and non-empty `entries` list. No default. |
| `appearance` | `quiet` or `tint`. Uses the site setting when omitted. |

Content belongs in `groups`. The default slot is accepted by the Markdown policy but is not displayed. Use `title` for a general header, or `method` with `path` for an endpoint header.

Each object in `entries` accepts these fields:

| Field | Values, default, and effect |
| --- | --- |
| `name` | **Required.** Non-empty text, unique within the group. |
| `annotation` | Type text, such as `string`. Omitted by default. |
| `required` | Boolean. Default: `false`. Adds a required badge. |
| `optional` | Boolean. Default: `false`. Adds `?` to the name. Do not combine with `required: true`. |
| `deprecated` | Boolean. Default: `false`. Marks an obsolete field. |
| `since` | Version text. Omitted by default. |
| `default` | Text describing the field's default value. Quote numbers and booleans, for example `default: "false"`. Omitted by default. |
| `description` | Text below the signature. Backticks format inline code. Omitted by default. |

Optional text fields must be non-empty when supplied. Invalid groups or entries stop rendering with a diagnostic; they are not silently removed. Generated entry IDs must be unique. Across multiple panels, use distinct group/name combinations to avoid duplicate anchors. The [API panel guide]($docs/components/api-reference) explains header variants and direct links to entries.

## img — ordinary Markdown images

Use Markdown image syntax for an image without a visible caption. The `img` tag is the built-in renderer for this syntax.

![A city skyline at sunset](/images/content-demo-workspace.jpg "City skyline")

**Copy into your Markdown file:**

````mdc [content/docs/component-example.md]

````

| Property | Values, default, and effect |
| --- | --- |
| `src` | Image path or URL; supplied inside parentheses. Needed to display an image. |
| `alt` | Alternative text; supplied inside square brackets. Describe meaningful images; use empty text only for decorative images. Default: empty text. |

## figure

Show an image with a caption. Select the image to try zoom; Escape closes it.

::figure{src="/images/content-demo-workspace.jpg" alt="High-rise buildings beneath a sunset sky" caption="The city at the end of the day." aspect="video" fit="cover"}
---
zoom: true
---
::

**Copy into your Markdown file:**

````mdc [content/docs/component-example.md]
::figure{src="/images/content-demo-workspace.jpg" alt="High-rise buildings beneath a sunset sky" caption="The city at the end of the day." aspect="video" fit="cover"}
---
zoom: true
---
::
````

| Property | Values, default, and effect |
| --- | --- |
| `src` | **Required.** Image path or URL. |
| `alt` | **Required.** Alternative text describing the image. |
| `caption` | Text below the image. No caption by default. |
| `width` | Number or numeric string. Explicit image width; unset by default. |
| `height` | Number or numeric string. Explicit image height; unset by default. |
| `bleed` | `outside` extends the figure beyond the text column. Omit for normal width. |
| `aspect` | `auto` (fallback), `video` (16:9), `wide` (21:9), `square` (1:1), or `portrait` (4:5). |
| `fit` | `cover` (fallback) fills and can crop; `contain` keeps the whole image inside the chosen aspect. |
| `zoom` | Boolean, or `auto` (default). `true` enables zoom; `false` disables it; `auto` follows the site setting. Put booleans in YAML. |
| `appearance` | `quiet` or `tint`. Uses the site setting when omitted. |

The default Markdown slot replaces `caption` with a rich caption. The Markdown policy accepts `bleed` as text: `"true"` also expands the figure; other text values keep normal width. Prefer `outside`.

## quiz and quiz-question

Let readers check what they learned. Choose an answer, check it, then view the result or try again.

::quiz{title="Check your draft" description="Try two questions."}
:::quiz-question
---
question: What helps someone understand an image they cannot see?
type: single
options:
  - text: Descriptive alternative text
    correct: true
  - text: A longer filename
    correct: false
---
Alternative text describes the image for people using a screen reader.
:::
:::quiz-question
---
question: What should you check before publishing?
type: multiple
options:
  - text: Links
    correct: true
  - text: Dates
    correct: true
  - text: The editor’s favorite color
    correct: false
---
Check that the links work and the dates are correct.
:::
::

**Copy into your Markdown file:**

````mdc [content/docs/component-example.md]
::quiz{title="Check your draft" description="Try two questions."}
:::quiz-question
---
question: What helps someone understand an image they cannot see?
type: single
options:
  - text: Descriptive alternative text
    correct: true
  - text: A longer filename
    correct: false
---
Alternative text describes the image for people using a screen reader.
:::
:::quiz-question
---
question: What should you check before publishing?
type: multiple
options:
  - text: Links
    correct: true
  - text: Dates
    correct: true
  - text: The editor’s favorite color
    correct: false
---
Check that the links work and the dates are correct.
:::
::
````

| Property | Values, default, and effect |
| --- | --- |
| `quiz.title` | Heading text. No title by default. |
| `quiz.description` | Introductory text. No description by default. |
| `quiz.appearance` | `quiet` or `tint`. Uses the site setting when omitted. |
| `quiz-question.question` | **Required.** Question text. |
| `quiz-question.type` | `single` (default) or `multiple`. |
| `quiz-question.options` | **Required.** YAML list of at least two choices, each with unique non-empty `text` and a boolean `correct`. |
| `quiz-question.explanation` | Text shown after checking. If omitted, uses the default Markdown slot. |

Put at least two `quiz-question` children in `quiz` to show navigation, results, and retry controls. Use `quiz-question` on its own for a single question with a retry button. For `single`, exactly one choice must have `correct: true`. For `multiple`, at least one must be correct; the reader must select all correct choices and no incorrect choices. Invalid options stop rendering with a diagnostic.

All interaction labels are optional text properties. They follow the page language when omitted. These are the built-in English and German defaults:

| Component | Property | English default | German default |
| --- | --- | --- | --- |
| `quiz` | `questionLabel` | Question | Frage |
| `quiz` | `backLabel` | Back | Zurück |
| `quiz` | `nextLabel` | Next | Weiter |
| `quiz` | `resultsLabel` | See Results | Ergebnis anzeigen |
| `quiz` | `correctSummaryLabel` | correct | richtig |
| `quiz` | `perfectLabel` | Perfect score! | Alles richtig. |
| `quiz` | `retryPrompt` | Keep learning and try again. | Weiterlernen und erneut versuchen. |
| `quiz` | `resetLabel` | Try Again | Erneut versuchen |
| `quiz-question` | `checkLabel` | Check Answer | Antwort pruefen |
| `quiz-question` | `correctLabel` | Correct | Richtig |
| `quiz-question` | `incorrectLabel` | Incorrect | Nicht richtig |
| `quiz-question` | `resetLabel` | Try Again | Erneut versuchen |
| `quiz-question` | `multipleChoiceLabel` | (select all that apply) | (mehrere Antworten möglich) |

Put an override on the component it belongs to, for example `:::quiz-question{checkLabel="Check my answer"}`. A question's `resetLabel` is used only outside a `quiz`; inside a quiz, the quiz reset controls all questions. Answers are practice feedback, not a saved assessment.

## toc

Insert a collapsible table of contents for this page. Open it to jump to a component.

::toc{title="Find a component"}
---
depth: 2
open: false
---
::

**Copy into your Markdown file:**

````mdc [content/docs/component-example.md]
::toc{title="Find a component"}
---
depth: 2
open: false
---
::
````

| Property | Values, default, and effect |
| --- | --- |
| `title` | Text. Default: the site’s translated table-of-contents label. |
| `depth` | Number. Keeps headings up to this level; `2` means level-two headings. Default: all headings supplied by the page TOC. |
| `open` | Boolean. Default: `false`. Sets whether the contents starts expanded. |

No slots or `appearance` property. This filters the existing page contents; it cannot add heading levels excluded by the page configuration. Nothing appears when the page supplies no headings.

## Ordinary Markdown and custom components

Paragraphs, headings, **bold text**, *emphasis*, lists, links, tables, blockquotes, horizontal rules, and code fences do not need an MDC tag. Ginko Docs styles them automatically. For example:

```md [content/docs/article.md]
## Before you publish

Check **names** and *dates*.

- Read the text.
- Open each link.

> Keep the reader's next action clear.

| Task | Owner |
| --- | --- |
| Review | Editorial team |

> [!NOTE]
> Save your draft before closing the editor.
```

GitHub-style alerts support `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, and `CAUTION`. Use a named notice component above when you need its title, icon, or appearance properties.

This page lists the built-in authoring contract. Site-specific tags need their own registration; they are not available on every Ginko Docs site. For example, `release-status` belongs to this documentation app's [custom component example]($docs/customization/custom-components). Ask the site developer to register a new component before using a custom tag.
