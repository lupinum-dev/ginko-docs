Ginko Docs is static-first and keeps Nitro as a first-class runtime. Choose the smallest profile that provides the request-time behavior you need.

## Choose a deployment target

| Profile | Page delivery | Same-URL Markdown | MCP |
| --- | --- | --- | --- |
| Pure Static | Generated files only | No; use `/raw/**.md` | No |
| Static + Provider Routing | Generated files with a small host routing function | Yes | Only when a Nitro function is also deployed |
| Nitro Runtime | Nitro server, serverless function, or container | Yes | Yes |

Use **Static + Provider Routing** as the normal documentation profile. Human pages, raw Markdown, LLM indexes, sitemaps, and social images remain generated files. The provider function only selects the correct generated representation from the incoming `Accept` header. Use **Pure Static** when zero request-time execution matters more than same-URL negotiation. Use **Nitro Runtime** when one portable server path matters more than static delivery.

The Copy Markdown menu uses the explicit raw route, so it works on static hosting when the generated `/raw/**.md` files are deployed. Its ChatGPT, Claude, and MCP entries are presentation controls; changing `markdownActions` does not enable or disable the underlying server routes.

## Generate a static site

Static delivery is the default:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    agent: { delivery: "static" },
  },
});
```

Run Nuxt generation from the consuming application:

```bash [terminal]
pnpm generate
```

Deploy the complete `.output/public` directory. Ginko Content contributes public page routes, raw Markdown, and LLM catalogs to prerendering. The layer also requests `/sitemap.xml`, `/robots.txt`, `/llms.txt`, and `/llms-full.txt` explicitly.

Serve the generated directory over HTTP before release:

```bash [terminal]
pnpm dlx serve .output/public
```

Opening an HTML file through `file://` does not test host routing, asset paths, redirects, or fallback behavior.

## Add provider routing to static output

The routing layer must require an explicit `text/markdown` range, compare weighted `q` values, keep HTML on ties unless Markdown is explicitly requested, exclude assets and machine endpoints, preserve the public URL, and add `Vary: Accept`. A missing raw file must stay a real `404` with a short Markdown recovery body.

The repository contains executable recipes and shared contract tests:

- [Vercel Routing Middleware](https://github.com/lupinum-dev/ginko-docs/blob/main/docs/middleware.ts)
- [Cloudflare Worker](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/cloudflare-worker.ts)
- [Netlify Edge Function](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/netlify-edge.ts)
- [Nginx](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/nginx.conf) and [Caddy](https://github.com/lupinum-dev/ginko-docs/blob/main/examples/agent-routing/Caddyfile) Nitro reverse proxies

For Vercel, place `middleware.ts` beside the deployed app's `package.json` and install `@vercel/functions`. The Ginko Docs site uses this profile in production. Cloudflare Workers must bind the static directory as `ASSETS` and run the Worker before assets. Netlify must declare the Edge Function for page paths. Keep the portable parsing and path-mapping helpers beside each provider wrapper so their tests exercise the same rules.

## Build a Nitro deployment

Select runtime delivery explicitly:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  content: {
    agent: { delivery: "runtime" },
  },
});
```

Build and preview the production server locally:

```bash [terminal]
pnpm build
pnpm preview
```

Deploy `.output` with the Nitro preset required by the host. Keep provider clients and credentials in server-only files. The filesystem provider uses the content snapshot prepared during the build; an external provider can read at request time when its runtime and credentials are available on the target.

Nitro handles weighted Markdown negotiation, response link headers, Markdown recovery responses, and `/mcp`. A CDN may cache those responses, but it must forward the `Accept` header and vary cached responses by `Accept`.

## Keep public URLs consistent

Use the same production origin wherever the site URL is configured:

```json [site.json]
{
  "name": "Example Docs",
  "description": "Documentation for Example.",
  "whenToUse": "Use this site to learn and operate Example.",
  "url": "https://docs.example.com"
}
```

```ts [content.config.ts]
import { defineGinkoDocsConfig } from "@lupinum/ginko-docs/content";
import site from "./site.json" with { type: "json" };

export default defineGinkoDocsConfig({
  site,
});
```

```ts [app/app.config.ts]
import site from "../site.json";

export default defineAppConfig({
  ginkoDocs: {
    site: {
      url: site.url,
    },
  },
});
```

```ts [nuxt.config.ts]
import site from "./site.json" with { type: "json" };

export default defineNuxtConfig({
  extends: ["@lupinum/ginko-docs"],
  site: { url: site.url },
  i18n: { baseUrl: site.url },
});
```

Ginko Docs uses the app-config URL for canonical links, structured data, raw links, and MCP links. Ginko Content reads the canonical origin from Nuxt Site configuration.

## Verify the deployed output

Check the deployment itself, not only the local build log:

- Direct-load the home page, the first docs page, a nested docs page, and a missing URL.
- Open representative pages in every configured locale and inspect canonical and alternate links.
- Follow the section switcher, sidebar links, previous and next links, and search results.
- Confirm `/sitemap.xml`, `/robots.txt`, `/llms.txt`, and `/llms-full.txt` return the expected content type.
- Fetch one generated `/raw/**.md` URL and confirm drafts and private data are absent.
- Request one page with HTML preferred and one with Markdown preferred. Confirm the content type and `Vary: Accept`.
- Request a missing page with Markdown preferred. Confirm a real `404` and recovery links.
- Call `/.well-known/ai-catalog.json`, `/mcp/server-card`, and `/mcp` only when the runtime profile advertises MCP.
- Inspect browser and server logs for hydration errors, missing assets, and failed social-image routes.
