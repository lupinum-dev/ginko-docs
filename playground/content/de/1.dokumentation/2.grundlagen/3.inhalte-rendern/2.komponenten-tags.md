Comark-kompatible Komponenten-Tags erlauben Docs-Autoren, wiederverwendbare Vue-Komponenten direkt in Markdown zu verwenden. Ginko Docs liefert die allgemeinen Dokumentationskomponenten; Consumer können projektspezifische Tags ergänzen.

## Consumer-definierte Komponente

Dieser Playground-Consumer – nicht der wiederverwendbare Layer – besitzt die Komponente `MdcReleaseStatus.vue`. Er registriert sie bei Vue, ordnet `release-status` in der Markdown-Tag-Map zu, deklariert die statische Render-Policy des Tags und registriert seinen eigenen Agent-Serializer aus `@lupinum/ginko-content/agent-registry`. Die Policy erlaubt nur die Props und Slots, die Autoren für diese Komponente wirklich benötigen.

::release-status{channel="Beta"}
Verfügbar für Projekte, die Preview-Releases ausdrücklich aktivieren.
::

## Callouts

::note{title="Notiz"}
Nutze Notizen fuer neutralen Kontext, der nah am umgebenden Fliesstext bleiben soll.
::

::info{title="Info"}
Nutze Info-Callouts fuer hilfreiche Details, Hintergrund und nicht-blockierende Hinweise zur Umsetzung.
::

::warning{title="Warnung"}
Nutze Warnungen, wenn Inhalte grundsaetzlich gueltig sind, aber vor dem Ausliefern Aufmerksamkeit brauchen.
::

::error{title="Fehler"}
Nutze Fehler fuer defekte Zustaende, ungueltige Konfiguration oder Schritte, die korrigiert werden muessen.
::

::success{title="Erfolg"}
Nutze Erfolg-Callouts fuer abgeschlossene Pruefungen, akzeptierte Ausgabe oder bestaetigtes Setup.
::

::idea{title="Idee"}
Nutze Ideen fuer optionale Verbesserungen, Alternativen oder spaetere Verfeinerungen.
::

::alert{title="Alert-Alias" type="info"}
Das `alert`-Tag nutzt dasselbe Callout-System und haelt bestehendes Markdown kompatibel.
::

::callout{title="Konfigurierbarer Callout" type="warning" icon="lucide:sparkles"}
Das Basis-Tag `callout` bleibt verfuegbar, wenn Autoren Typ oder Icon direkt auswaehlen wollen.
::

## Schritte

:::
