Diese Seite ist die visuelle Fixture für den vollständigen Komponentensatz. Sie rendert jedes öffentliche Autoren-Tag mit realistischen Inhalten, damit Maintainer Abstände, Typografie, Interaktion, responsives Verhalten und Theme-Darstellung gemeinsam vergleichen können.

## Hinweise und ergänzende Prosa

Semantische Hinweise vermitteln unterschiedliche Kontexte, ohne den Lesefluss zu verändern.

::note{title="Hintergrund"}
Numerische Präfixe steuern die Reihenfolge, erscheinen aber nie in öffentlichen Routen.
::

::info{title="Generiertes Verhalten"}
Navigation, Suche und agentenlesbare Ausgabe leiten sich aus denselben Content-Dokumenten ab.
::

::warning{title="Übersetzte Identitäten prüfen"}
Behalte für gleichwertige englische und deutsche Seiten dieselbe numerische Identität bei.
::

::success{title="Bereit zur Veröffentlichung"}
Content, Navigation und öffentliche Referenzen haben die Validierung bestanden.
::

::error{title="Konfiguration fehlgeschlagen"}
Die konfigurierte Collection enthält keine passende Route.
::

::idea{title="Redaktionelle Idee"}
Verwende ein fokussiertes Beispiel, bevor du eine vollständige Referenztabelle ergänzt.
::

::alert{title="Kompatibilitätswarnung" type="danger"}
Aktualisiere den Layer und seine Peer-Abhängigkeit als einen unterstützten Satz.
::

::callout{title="Eigener Callout" type="note" icon="lucide:book-open"}
Der generische Callout akzeptiert einen expliziten semantischen Typ und ein Icon.
::

::danger{title="Danger-Alias"}
Dieses Tag rendert dieselbe Fehlerdarstellung wie `error`.
::

::warn{title="Warn-Alias"}
Dieses Tag rendert dieselbe Warnungsdarstellung wie `warning`.
::

::aside{label="Redaktioneller Hinweis"}
Ein Aside ergänzt nützlichen Kontext, der für die Hauptaufgabe nicht erforderlich ist.
::

::passage{label="Auszug"}
Ein Content-Modell versorgt die gerenderte Seite, den Suchdatensatz, Raw-Markdown und den Agentenkatalog.
::

::dropcap{lines="3"}
Ginko Docs verwandelt strukturiertes Markdown in eine Dokumentationswebsite für Leser und Software-Agenten. Das Initial gibt längeren redaktionellen Passagen einen eigenen Einstieg, ohne ihre Quellstruktur zu verändern.
::

Inline-Steuerelemente können plattformabhängige Tastenkürzel zeigen: :kbd{value="meta"} + :shortcut{value="K" size="sm"}.

## Akkordeons

::accordion{type="single"}
:::accordion-item{value="content" title="Wer besitzt das Content-Modell?"}
Ginko Content besitzt Dokumentidentität, Routen, Sprachvarianten, Suchdaten und Agentendarstellungen.
:::

:::accordion-item{value="presentation" title="Wer besitzt die Darstellung?"}
Ginko Docs besitzt Dokumentations-Shell, Komponentenstile, Navigationssteuerung und responsives Verhalten.
:::

## Schritte und Zeitleiste

::steps{variant="numbered"}
:::step{title="Pakete installieren"}
Füge Ginko Docs und Ginko Content zum konsumierenden Nuxt-Projekt hinzu.
:::
:::step{title="Layer erweitern"}
Füge `@lupinum/ginko-docs` zum Nuxt-Array `extends` hinzu.
:::
:::step{title="Erste Seite schreiben"}
Erstelle ein Markdown-Dokument mit Titel und Beschreibung.
:::
::

::steps{variant="icons"}
:::step{title="Verfassen" icon="lucide:file-pen-line"}
Schreibe das kanonische Dokument einmal.
:::
:::step{title="Bauen" icon="lucide:hammer"}
Erzeuge die menschen- und agentenlesbaren Ausgaben.
:::
::
