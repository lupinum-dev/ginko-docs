Markdown should cover the common writing surface without requiring custom components.

## Paragraphs and emphasis

Use paragraphs for documentation prose. Use **strong text** when the reader must notice a constraint, and use `inline code` for commands, paths, function names, and config keys.

Use `const locale = "en"`{lang="ts"} when an inline snippet needs syntax highlighting.

## Lists

Use ordered steps for procedures:

1. Define the collection.
2. Query the collection.
3. Render the document.
4. Verify generated output.

Use unordered lists for related facts:

- Routes come from collection paths.
- TOC links come from headings.
- Search comes from parsed content.

## Code

A regular code block renders with syntax highlighting:

```ts
import { docs } from "~/content.config";

const { page } = await useContentPage(docs);
```

Place line numbers after the language to highlight specific lines:

```ts [content.config.ts]
import { defineContentConfig } from "@lupinum/ginko-content/config";

export const docs = defineContentConfig({
  root: "content/en",
});
```

Use Shiki notation when a line should be highlighted independently from the code fence metadata:

```ts [content.config.ts]
const source = "content/en";
const collection = "docs"; // [!code highlight]
const locale = "en";
```

Use Shiki diff notation when added and deleted lines need to be visible:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ["@nuxt/content"], // [!code --]
  modules: ["@lupinum/ginko-content"], // [!code ++]
});
```

## Footnotes

Footnotes link a reference in the text to a definition at the end of the document.[^markdown-footnotes]

[^markdown-footnotes]: The footnotes list is generated from the definitions that are actually referenced.
