Comark-compatible component tags let docs authors use reusable Vue components inside Markdown. Ginko Docs supplies the general documentation components; consumers can add project-specific tags without changing the layer.

## Consumer-defined component

This playground consumer—not the reusable layer—owns the `MdcReleaseStatus.vue` component. It registers the component with Vue, maps `release-status` in its Markdown tag map, declares the tag's static render policy, and registers its custom agent serializer from `@lupinum/ginko-content/agent-registry`. The policy admits only the authored props and slots the component supports; copied and agent-facing Markdown becomes a concise blockquote instead of leaking an implementation-only component tag.

::release-status{channel="Beta"}
Available to projects that explicitly enable preview releases.
::

## Callouts

::note{title="Note"}
Use notes for neutral context that should stay close to the surrounding prose.
::

::info{title="Info"}
Use info callouts for helpful details, background, and non-blocking implementation hints.
::

::warning{title="Warning"}
Use warnings when content can be valid but needs attention before it ships.
::

::error{title="Error"}
Use errors for broken states, invalid configuration, or steps that must be corrected.
::

::success{title="Success"}
Use success callouts for completed checks, accepted output, or confirmed setup.
::

::idea{title="Idea"}
Use ideas for optional improvements, alternatives, or follow-up refinements.
::

::alert{title="Alert alias" type="info"}
The `alert` tag wraps the same callout system and keeps existing Markdown compatible.
::

::callout{title="Configurable callout" type="warning" icon="lucide:sparkles"}
The base `callout` tag remains available when authors need to choose the type or icon directly.
::
