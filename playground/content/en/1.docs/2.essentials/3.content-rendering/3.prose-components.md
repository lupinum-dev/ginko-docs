Prose components style normal Markdown tags. Ginko Docs includes them directly so content stays readable without requiring every page to use custom components.

## Headings

Headings produce IDs and table of contents entries. The right rail should highlight the active heading while scrolling.

### Subheading

The hierarchy of `h2`, `h3`, and `h4` should feel calm: enough spacing for orientation, without oversized jumps in the reading flow.

#### Detail heading

Detail headings mark short subsections without visually breaking the paragraph that follows.

## Text, links, and lists

Paragraph text stays narrow enough to read, uses a clear line height, and can highlight **important terms**. Emphasis like _editorial notes_ and inline code such as `siteConfig.site.name` must sit cleanly inside a sentence.

Internal links such as [Markdown syntax]($docs/essentials/markdown-syntax) and external links such as [Nuxt](https://nuxt.com) use the same prose link component.

- Unordered lists have compact, but not cramped, rows.
- Nested lists remain readable:
  - second level with its own marker
  - enough spacing before the next item
- Long list text can wrap without making the marker and text alignment feel unstable.

1. Ordered lists show clear steps.
2. Numbering should stay stable with multi-line text.
3. Nested entries work too:
   1. first sub-step
   2. second sub-step

> A quote or editorial note should feel like part of the reading flow: visibly separated, but not like a heavy card.

## Tables

Tables should keep compact spacing and borders:

| Element | Component    | Purpose                 |
| ------- | ------------ | ----------------------- |
| `p`     | `ProseP`     | readable text measure   |
| `h2`    | `ProseH2`    | section structure       |
| `pre`   | `ProsePre`   | code block with copy UI |
| `table` | `ProseTable` | compact comparison data |
