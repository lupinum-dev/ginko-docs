Docs navigation is derived from the docs collection tree. The app should not keep a second manual sidebar source.

## Metadata

Starter navigation metadata lives next to content. Use page frontmatter for route pages and `.navigation.yml` sidecars for folder-level labels, icons, badges, and grouping.

To change a section tab or group heading, edit the folder sidecar:

```yaml
# content/en/1.docs/2.essentials/3.content-rendering/.navigation.yml
title: Rich Rendering
icon: lucide:brush-cleaning
sidebar: group
```

Use an index page only when the folder should also have a landing page route. Without `1.index.md` or `index.md`, the sidecar still creates the group heading and the sidebar lists the child pages directly.

## Sections

Top-level docs folders marked with `sidebar: section` become tabs in the sidebar. Their children become the visible list for the active tab.

## Groups

Folders marked with `sidebar: group` become local headings inside a section. They are useful when a section has several pages that belong together, such as rendering pages.

## Active state

The active section is resolved from the current route. The active page is resolved by exact path or by matching nested children.

::alert{title="Migration check" type="info"}
If a sidebar item appears in content but not in the UI, the normalizer is dropping data and must be fixed.
::

## Mobile

Mobile keeps the sidebar and table of contents as separate sheet controls. That mirrors the desktop split and avoids mixing page navigation with heading navigation.
