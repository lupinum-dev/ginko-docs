Ginko Docs maps 46 authored tags to its prose and MDC components. The map and portable component policy are exported from `@lupinum/ginko-docs/components`; the table below is the complete author-facing contract from `layer/tags.ts`.

Use static values in Markdown. Dynamic Vue bindings are rejected by the content policy.

```mdc [content/docs/example.md]
::callout{title="Check the route" type="warning" icon="lucide:triangle-alert"}
Use the public route, not the source filename.
::
```

## Reading the tables

- A prop marked **required** must be authored.
- `asset` is a media reference handled by the content portability contract.
- `default` means content written between the opening and closing tags.
- A dash means that the portable authoring policy exposes no prop or slot.

Implementation-only Vue props such as `class`, `inStack`, or quiz state are intentionally excluded. They are not part of the authored Markdown contract.

## Accordions

| Tag              | Component          | Public props                                                                                  | Slots                         |
| ---------------- | ------------------ | --------------------------------------------------------------------------------------------- | ----------------------------- |
| `accordion`      | `MdcAccordion`     | `type?: 'single' \| 'multiple'`, `collapsible?: boolean`, `defaultValue?: string \| string[]` | `default`                     |
| `accordion-item` | `MdcAccordionItem` | `value?: string`, `title?: string`, `content?: string`                                        | `default`, `title`, `content` |

Nest `accordion-item` inside `accordion`. Use named slots when a title or content block needs Markdown instead of a plain string.

## Code and file trees

| Tag          | Component      | Public props                                                                   | Slots     |
| ------------ | -------------- | ------------------------------------------------------------------------------ | --------- |
| `code-group` | `MdcCodeGroup` | —                                                                              | `default` |
| `code-tree`  | `MdcCodeTree`  | `defaultValue?: string`, `expandAll?: boolean`                                 | `default` |
| `collapse`   | `MdcCollapse`  | —                                                                              | `default` |
| `file`       | `MdcFile`      | **`name: string`**, `icon?: string`, `annotation?: string`, `active?: boolean` | —         |
| `files`      | `MdcFiles`     | `highlight?: string`                                                           | `default` |
| `folder`     | `MdcFolder`    | **`name: string`**, `open?: boolean`, `icon?: string`, `active?: boolean`      | `default` |

Code groups and code trees derive their entries from labeled fenced-code blocks. File trees use `files` as the root and allow nested `folder` and `file` tags. `collapse` clips tall content — usually one long fenced example — behind a "Show all lines" control; content that fits its height renders unchanged.

```mdc [content/docs/project-structure.md]
::files{highlight="app/app.config.ts"}
:::folder{name="app"}
::::file{name="app.config.ts" annotation="site identity"}
::::
:::
::
```

`img` maps normal Markdown images to `ProseImg`; it is the only exported tag without a separate portable-policy entry. Author it with ordinary Markdown syntax:

```md [content/docs/images.md]
![Detailed planning material arranged for a website content session](/images/content-demo-detail.png)
```

Use `figure` when you need an explicit caption, dimensions, aspect, fit, bleed, or per-image zoom policy. With the default `ginkoDocs.images.zoom: true`, select this image to see its thumbnail morph into the dialog:

:::

## Quizzes

| Tag             | Component         | Public props                                                                                                                                                                                                                                                                        | Slots     |
| --------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `quiz`          | `MdcQuiz`         | `title?: string`, `description?: string`, `questionLabel?: string`, `backLabel?: string`, `nextLabel?: string`, `resultsLabel?: string`, `correctSummaryLabel?: string`, `perfectLabel?: string`, `retryPrompt?: string`, `resetLabel?: string`                                     | `default` |
| `quiz-option`   | `MdcQuizOption`   | `correct?: boolean`, `label?: string`                                                                                                                                                                                                                                               | `default` |
| `quiz-question` | `MdcQuizQuestion` | **`question: string`**, `type?: 'single' \| 'multiple'`, `explanation?: string`, `options?: Array<string \| { text: string; correct?: boolean }>`, `checkLabel?: string`, `correctLabel?: string`, `incorrectLabel?: string`, `resetLabel?: string`, `multipleChoiceLabel?: string` | `default` |

Nest questions in `quiz`. A question can receive static `options` data or nested `quiz-option` tags. The label props let an authored quiz override its interaction copy without changing the site locale messages.

## Extend the tag map

Merge the public map instead of copying the 46 built-ins:

```ts [nuxt.config.ts]
import { ginkoDocsComponentTags } from "@lupinum/ginko-docs/components";

export default defineNuxtConfig({
  content: {
    componentPolicy: {
      components: {
        "api-playground": {
          kind: "block",
          props: {
            method: { type: "string", required: true },
            path: { type: "string", required: true },
          },
          slots: ["default"],
          media: null,
        },
      },
    },
    markdown: {
      tags: {
        ...ginkoDocsComponentTags,
        "api-playground": "MdcApiPlayground",
      },
    },
  },
});
```

Register a custom MDC component globally because the Markdown renderer resolves tag targets dynamically. Register a Ginko Content agent serializer when copied or raw Markdown needs a representation other than the default XML-style component output.
